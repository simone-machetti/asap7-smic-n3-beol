# ASAP7 SMIC N+3 BEOL

ASAP7 platform trees for the RTL sandbox flow: the stock OpenROAD-flow-scripts ASAP7 and a variant whose back end of line (BEOL) is to be restacked toward SMIC N+3. The flow selects one of them with `PLATFORM=<name>`, so the same design runs on both technologies from one checkout.

## Layout

```
.
├── vendor/                         # Upstream copies, generated by vendor.py and never edited
│   ├── vendor.py                   # Vendoring tool
│   ├── asap7.vendor.hjson          # OpenROAD-flow-scripts, flow/platforms/asap7
│   ├── asap7sc7p5t_27.vendor.hjson # ASU cell-library repository, Verilog models only
│   ├── *.lock.hjson                # Resolved revisions (generated, not tracked)
│   ├── asap7/                      # Generated, not tracked
│   └── asap7sc7p5t_27/             # Generated, not tracked
└── platforms/
    ├── assemble.sh                 # Builds every platform directory from vendor/, shared/ and overlays/
    ├── overlays/                   # Authored files of each variant, same relative paths as the platform
    │   └── asap7-smic-n3/          # The restacked BEOL files
    ├── shared/                     # Liberty files unpacked from vendor/ (generated, not tracked)
    ├── asap7/                      # Stock ASAP7: links into vendor/ and shared/ (generated, not tracked)
    └── asap7-smic-n3/              # The same links with the overlay files on top (generated, not tracked)
```

## Platforms

Every directory under `platforms/` except `overlays/` and `shared/` is a complete ASAP7 platform in the OpenROAD-flow-scripts layout, made only of links: into the vendored trees, into `shared/` and, for a variant, into its `overlays/<name>/` folder, whose files take precedence over the vendored ones at the same relative path. The two platforms therefore differ only in the overlay:

| File                                         | `asap7` | `asap7-smic-n3` | Role                                    |
| -------------------------------------------- | ------- | --------------- | --------------------------------------- |
| `lef/asap7_tech_1x_201209.lef`               | vendor  | overlay         | Metal stack: layers, pitches, vias      |
| `openRoad/make_tracks.tcl`                   | vendor  | overlay         | Routing tracks per layer                |
| `openRoad/pdn/grid_strategy-M1-M2-M5-M6.tcl` | vendor  | overlay         | Flat power-grid strategy                |
| `setRC.tcl`                                  | vendor  | overlay         | Per-layer wire RC estimates             |
| `rcx_patterns.rules`                         | vendor  | overlay         | Parasitic extraction rules              |
| `KLayout/asap7.lyt`, `KLayout/asap7.lyp`     | vendor  | overlay         | Layer map and display for the GDS merge |

Status: the overlay files of `asap7-smic-n3` are byte-identical copies of the stock ones. The two platforms therefore give identical results, which is the check that the selection mechanism works before any BEOL change is made.

Two additions to the stock package, present in both platforms:

- `verilog/stdcell/` also holds the ASU Verilog models the package lacks (the OA group and the LVT, SLVT and SRAM flavors), linked from `vendor/asap7sc7p5t_27/`.
- `lib/NLDM/` holds the uncompressed RVT TT liberty files (upstream ships them gzipped and the flow reads them uncompressed), linked from `platforms/shared/`.

## Use with the flow

```bash
export PDK_HOME=/path/to/asap7-smic-n3-beol # once, in ~/.bashrc

make pnr ...                                # stock ASAP7 (PLATFORM=asap7, the default)
make pnr ... PLATFORM=asap7-smic-n3         # restacked variant
```

The flow's Makefile resolves the technology tree as `$PDK_HOME/platforms/$PLATFORM`. `PLATFORM` is accepted by every technology-dependent target (`syn`, `pnr`, the `post-*` analyses and simulations); name the output folder after the platform to tell the runs apart.

## Rebuilding

Only the descriptors, the overlays and `assemble.sh` are tracked; the vendored trees, the lock files and the platform directories are generated. Run this after cloning, and again after changing a descriptor or adding an overlay:

```bash
cd vendor
python3 vendor.py asap7.vendor.hjson
python3 vendor.py asap7sc7p5t_27.vendor.hjson
cd ..
bash platforms/assemble.sh
```

`vendor.py` clones the full upstream repositories (about 0.9 GB and 2.7 GB of history) into a temporary directory and rebuilds `vendor/<name>/` from scratch; run it from `vendor/`, since it moves the repository's `.git` aside for the duration of the run. `assemble.sh` unpacks the liberty files into `platforms/shared/` and rebuilds every platform directory from scratch: `asap7` from the vendored trees, and one platform per `platforms/overlays/<name>/` with the overlay files linked on top. Edit the overlay files, never the platform directories. The `rev` field of each descriptor pins the upstream revision, so every clone rebuilds the same trees.
