# Extraction rules

`rcx_patterns.rules`, generated by `make_rcx_rules.py`

## What the file is for

After routing, an extractor turns the layout into the network of resistances and capacitances that post-route timing and power are computed from. This file is its model of the process: for a wire of a given layer, in a given surrounding, how much capacitance per unit length it has to its neighbours and to the layers above and below, and how much resistance.

## What ASAP7's version contains

It states a layer count, ten: M1 to M9 and the Pad layer. Then, for every layer, it holds sets of tables, each for one surrounding:

| Table set   | Surrounding of the wire                                         |
| ----------- | --------------------------------------------------------------- |
| `RESOVER`   | Resistance, against the distance to the neighbour on each side  |
| `OVER`      | Over a conducting plane at a lower layer, or over the substrate |
| `UNDER`     | Under a plane at a higher layer                                 |
| `DIAGUNDER` | Diagonal coupling to a wire at a higher layer                   |
| `OVERUNDER` | Between a plane below and a plane above                         |

A row of a capacitance table gives a distance to the neighbouring wire, the coupling capacitance to it, the capacitance to the planes, and a resistance. The distances are fixed multiples of the wire width, from 1 to 12. In all there are about 320 tables. Some are declared and left empty: diagonal coupling beyond four layers, and everything under the Pad layer.

Upstream generated the file with a field solver, a program that solves the electric field around the actual three-dimensional shapes. None is available here. A circuit simulator cannot substitute: it solves circuits that are already described by resistors and capacitors, and has no notion of geometry.

## What changed and why

**The tables are transformed, not recomputed.** They are functions of the distance to the neighbouring wires, and capacitance per unit length does not change when every dimension of the cross-section scales together. So each table of the new stack is an ASAP7 table of the nearest width class, with its distance axis rescaled to the new wire width.

| Layers    | Tables taken from     | Distance axis | Resistance     |
| --------- | --------------------- | ------------- | -------------- |
| M1, M2    | ASAP7's M1, M2        | unchanged     | unchanged      |
| M3        | ASAP7's M3, 18 nm     | times 22/18   | times (18/22)² |
| M4 to M6  | ASAP7's M8, 40 nm     | unchanged     | unchanged      |
| M7 to M10 | ASAP7's M8            | times 1.6     | times (40/64)² |
| M11       | ASAP7's M8            | times 1.85    | times (40/74)² |
| Pad       | ASAP7's Pad, all zero | unchanged     | unchanged      |

**Surroundings are matched by vertical distance.** The new stack has twelve layers against ten, and its layers sit at other positions, so the table of the new M5 under M7 cannot be "ASAP7's M5 under M7". It is the table of an ASAP7 layer under the layer two above it. Where the preferred source layer has no table at that distance, the nearest lower ASAP7 layer that has one supplies it; its distance axis is rescaled like any other. Distances beyond ASAP7's reach are clamped to the farthest plane available, whose influence is already marginal. Tables that ASAP7 leaves empty stay empty.

**The resistance of every table is that of the layer itself**, whichever ASAP7 layer its capacitances come from, and it is the resistance of [setRC.md](setRC.md), so the estimate before routing and the extraction after it agree.

**The format is reproduced exactly.** The extractor reads the file strictly in order, layer by layer and table set by table set, with no tolerance for a missing block; the layer count must equal the number of routing layers of the technology LEF, Pad included. The new file states twelve and holds about 500 tables.

**The generator proves itself.** Run with `--self-test`, the script rebuilds ASAP7's own file from a description of ASAP7's own stack, and the result must match the original byte for byte. That checks the parsing, the choice of tables and the output format before the script is trusted on a new stack.

The consequence has to travel with the file: parasitics extracted with it are modelled, not characterised.

## How to change it again

The stack is described by a short table at the top of `make_rcx_rules.py`: for every layer of the new stack, the ASAP7 layer its tables come from, its width, and its resistance factor. After editing it:

```bash
cd beol/smic-n3
python3 make_rcx_rules.py --self-test ../../vendor/asap7/rcx_patterns.rules
python3 make_rcx_rules.py ../../vendor/asap7/rcx_patterns.rules rcx_patterns.rules
```

Never edit `rcx_patterns.rules` by hand. The real upgrade is a field-solver run on a three-dimensional model of the stack, fed through the extractor's own pattern-generation flow; it would replace the generated file and leave everything else as it is.
